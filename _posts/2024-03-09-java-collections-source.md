#### 数组的特性

**数组的特性： **

1.数组必须先定义**固定长度**，**不能适应数据动态增减 **

2.当数据增加时，可**能超出原先定义的元素个数，当数据减少时，造成内存浪费 **

3**.数组查询比较方便，根据下标就可以直接找到元素，时间复杂度 O(1)；增加和删除比较复杂，需要移动操作数所 **

### 链表

#### 链表的特性
**链表的特性： **

1. 链表动态进行存储分配，可适应数据动态增减

2. 插入、删除数据比较方便,时间复杂度 O(1)；查询必须从头开始找起，十分麻烦，时间复杂度 O(N)

常见的链表:

1. 单链表：通常链表每一个元素都要保存一个指向下一个元素的指针

2. 双链表：每个元素既要保存到下一个元素的指针，还要保存一个上一个元素的指针

3. 循环链表：在最后一个元素中下一个元素指针指向首元素

链表和数组都是在堆里分配内存

**应用： **

如果需要快速访问数据，很少或不插入和删除元素，就应该用数组；相反， 如果需要经常插入和删除元素就需要

用链表数据结构了

### 散列表

散列表（Hash Table），也称为哈希表或哈希映射，是一种用于高效存储和检索数据的数据结构。它通过将键（Key）映射到值（Value）的方式来存储数据，使得通过键可以快速地访问对应的值。

散列表的核心思想是使用哈希函数将键映射到散列表的桶（Bucket）或槽（Slot）上。桶可以看作是一个数组，每个桶存储一个键值对。当需要存储或检索数据时，根据键通过哈希函数计算得到对应的桶的索引，在该桶中进行操作。

散列表具有以下特点：

1. 快速的查找和插入：通过哈希函数，可以在常数时间复杂度下定位到对应的桶，从而实现快速的查找和插入操作。

2. 高效的存储和检索：散列表适用于大量数据的存储和检索，可以在较短的时间内完成查找和插入操作。

3. 冲突处理：由于可能存在不同的键映射到同一个桶的情况，称为冲突。常见的冲突处理方法包括链表法和开放寻址法等。

散列表的性能取决于以下因素：

1. 哈希函数的设计：好的哈希函数能够将键均匀地映射到桶中，尽量避免冲突，提高散列表的性能。

2. 散列表的装载因子：装载因子指已存储的键值对数量与散列表大小的比值。较低的装载因子可以减少冲突的概率，但会增加散列表的空间占用。

3. 冲突处理方法的选择：不同的冲突处理方法在不同的场景下表现不同，选择合适的冲突处理方法有助于提高散列表的性能。

散列表在实际应用中广泛使用，例如缓存系统、数据库索引、编译器中的符号表等。它能够以较高的效率存储和检索数据，并在大多数情况下具有良好的性能。

#### 相关细节

1. 在**集合或数组扩容**时，通常会**创建一个新的数组**，并将**原有的元素拷贝到新的数组**中。这意味着在扩容过程中会**创建一个新的引用，而不是使用原来的引用**。当集合或数组需要扩容时，原有的数组可能无法容纳更多的元素。为了解决这个问题，会创建一个更大的数组，并将原有数组中的元素逐个拷贝到新数组中。这样做的目的是保留原有数组中的元素，并且提供更多的空间来存储新的元素。在拷贝过程中，新的数组会被创建，并且原有数组中的元素会被复制到新数组中相应的位置。因此，新的数组会有一个新的引用，而不是使用原来数组的引用。需要注意的是，扩容并不仅仅是简单地拷贝元素到新数组中。通常情况下，还会根据具体的实现策略进行一些额外的操作，比如重新计算哈希码、重新构建索引等，以保证集合或数组的性能和正确性。总结起来，集合或数组的扩容过程会创建一个新的数组，并将原有的元素拷贝到新数组中。因此，在**扩容后会使用新的引用来引用新的数组**。

2. 数组中元素的引用也是新的吗？

在数组扩容的过程中，如果数组存储的是对象或其他引用类型的数据，那么拷贝的过程中会复制元素的引用，而不会创建新的对象或引用。具体来说，当数组需要扩容时，新的更大容量的数组会被创建。然后，原始数组中的元素引用会被逐个复制到新的数组中，保持元素的顺序不变。这意味着新数组中的元素引用与原始数组中的元素引用指向的是相同的对象。

换句话说，数组的扩容过程只是创建了一个新的存储空间，并将原有元素的引用复制到新的存储空间中，而不是创建新的对象或引用。需要注意的是，如果数组存储的是可变对象（例如列表或字典），那么在对原始数组中的元素进行修改时，会影响到新数组中相应位置的元素，因为它们引用的是同一个对象。这是因为数组中存储的是对象引用，而不是对象本身。综上所述，数组扩容过程中，元素的引用是复制到新数组中的，而不是创建新的引用。这意味着新**数组中的元素引用与原数组中的元素引用指向相同的对象**。

1. 首先对key进行空置检查，如果为null,那么将底层数组为[0]的袁术返回，     [0] == null

2. 不为Null的的key,进行hash值的获取，然后利用某种算法，得到这个元素在数组中的指针位置，然后这个位置下标如果有值，比较HashCode是否一样，然后在比较equals()是否为true，是就返回

### HashMap 和 HashTable 区别

**（****1****）线程安全性不同 **

HashMap 是线程不安全的，HashTable 是线程安全的，其中的方法是 Synchronize 的，在多线程并发的情况下，可以

直接使用 HashTabl，但是使用 HashMap 时必须自己增加同步处理。

**（****2****）是否提供 ****contains ****方法 **

HashMap 只有 containsValue 和 containsKey 方法；HashTable 有 contains、containsKey 和 containsValue 三个方法，其

中 contains 和 containsValue 方法功能相同。

**（****3****）****key ****和 ****value ****是否允许 ****null ****值 **

Hashtable 中，key 和 value 都不允许出现 null 值。HashMap 中，null 可以作为键，这样的键只有一个；可以有一个

或多个键所对应的值为 null。

**（****4****）数组初始化和扩容机制 **

HashTable 在不指定容量的情况下的默认容量为 11，而 HashMap 为 16，Hashtable 不要求底层数组的容量一定要为

2 的整数次幂，而 HashMap 则要求一定为 2 的整数次幂。

Hashtable 扩容时，将容量变为原来的 2 倍加 1，而 HashMap 扩容时，将容量变为原来的 2 倍。

**（5）HashMap 这一块很重要，面试工作都很经常用，如有需要，请务必看一下源码分析**
