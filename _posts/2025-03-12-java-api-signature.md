## 概述
为保证API请求的安全性，防止数据篡改和重放攻击，所有请求需进行签名（加签）和验证签名（验签）。本文档详细说明加签、验签流程及注意事项。

## 加签流程

### 准备请求参数

- 包含业务参数的 `Map` 集合（如 `param1`, `param2`）。

- **必传系统参数**：
    - `appId`: 应用唯一标识（由服务方分配）。
    - `secret`: 密钥（由服务方分配，**需保密**）。
    - `timestamp`: 当前时间戳（秒级，如 `1620000000`）。

### 生成待签名字符串

1. **过滤并转换参数** 将参数值转为字符串类型，排除空值或无效参数。

2. **按Key字典序排序** 对所有参数Key按字母升序排列（如 `a=1`, `b=2` 排序后为 `a=1&b=2`）。

3. **拼接参数** 格式为 `key1=value1&key2=value2`（无转义符和空格）。

### 计算签名值

- **算法**: HMAC-SHA256
- **密钥**: `appId` 的UTF-8字节（非`secret`）。

- **签名生成步骤**：
    - 使用密钥对“待签名字符串”进行HMAC-SHA256加密。
    - 将加密结果转为十六进制大写字符串，作为最终签名 `sign`。

### 设置请求头

```http
sign: {生成的签名值}
timestamp: {请求中的timestamp值}
appId: {服务方分配的id}

```

- **注意**: 请求中无需传递 `secret` 参数。

## 验签流程（服务端）

### 获取必要信息

- 从请求头获取 sign 和 timestamp。

- 从请求参数获取 `appId` 和其他业务参数。

### 检查时间戳有效性

- 解析 **timestamp**，与服务器当前时间对比，30分钟超时。

### 重新生成签名

**补充系统参数**
    1. 添加 `secret`（服务端存储的密钥）、`appId`、`timestamp` 到参数列表。

2. **生成待签名字符串** 按字典序排序并拼接参数，步骤同加签流程。

3. **计算签名** 使用 `appId` 作为HMAC密钥，生成签名。

### 比对签名

- 比较请求头中的 `sign` 与服务器生成的签名是否一致。

- **不一致**则拒绝请求，返回验签失败。

## 请求示例

### 加签请求示例
**原始参数**：

```json
{
  "orderId": "123456",
  "amount": "100.00"
}

```
**加签后请求头**：

```http
POST /api/createOrder HTTP/1.1
sign: 1A2B3C4D5E6F7890ABCDEF...
timestamp: 1620000000
appId: 215126534430654464

```

## 注意事项

**密钥安全**
    1. `secret` 必须保密存储，禁止在客户端或网络传输中暴露。

2. **时间戳防重放**
    1. 服务端会校验时间戳有效性，旧请求不要重复发送。

3. **参数顺序一致性**
    1. 参数排序必须严格按照Key字典序，否则会导致签名不一致。

4. **编码格式**
    1. 所有参数必须使用UTF-8编码，避免编码不一致引发验签失败。
